# Operations وProviders — القائمة الحالية والقرارات المقترحة

**الحالة:** جرد عمليات لم يتغير؛ أضيف في Gateway عرض الدعم الفعّال لكل Model دون إضافة Operations جديدة.

## 1. Operations الموجودة في عقد Gateway الحالي

| Operation | حالة الكود الحالي | اقتراح المرحلة الجديدة |
|---|---|---|
| `generate_text` | في Enum وتعلنه عدة Providers | إبقاؤها في العقد الأساسي؛ streaming نمط تنفيذ منفصل لها |
| `generate_image` | في Enum، معلنة بواسطة IvyCraft | إبقاؤها؛ النتائج الكبيرة تستفيد من Asset Reference موحّد |
| `transcribe_audio` | في Enum، معلنة بواسطة DeepAI وOverchat | إبقاؤها؛ Capability اصطلاحية مرشحة `audio.transcription` |
| `synthesize_speech` | في Enum، معلنة بواسطة IvyCraft وNoteGPT | إبقاؤها كتحويل نص إلى كلام؛ ليست توليد موسيقى/صوت عام |
| `create_embeddings` | في Enum، معلنة بواسطة Voyage | إبقاؤها |
| `rerank_documents` | في Enum، معلنة بواسطة Voyage | إبقاؤها |
| `moderate_content` | موجودة في Enum والوثائق، لكن لا Provider مسجل يعلنها في المراجعة | فجوة: إما تنفيذها واختبارها قبل عرضها تشغيليًا، أو إبقاؤها مرشحة خارج الكتالوج النشط حتى ذلك الحين |
| `analyze_vision` | في Enum ومعلنة بواسطة عدة Providers | إبقاؤها؛ ربطها بمدخلات الصور عبر Asset Reference موحّد |

**الوضع المنفذ:** لا نخلط بين وجود اسم في المصدر وبين توفره للمستهلك. `/v1/providers`, `/v1/describe`, و`/v1/models` تعرض الآن Operations/Capabilities الفعّالة لكل Model بعد حل Provider defaults والـoverrides. لم تُضف Operation جديدة، ولا يُعلن دعم `moderate_content` بلا Provider منفذ.

## 2. المرشحون قبل تثبيت العقد الأساسي

| المرشح | نوعه المقترح | التوصية الأولية | شرط الإدراج التشغيلي |
|---|---|---|---|
| `generate_video` | Operation | مؤجلة؛ الفيديو كان مثالًا على عملية طويلة وليس شرطًا لأقل بداية سليمة | تضاف لاحقًا عند حاجة منتج واضحة، مع عقد Job وAsset Reference وتنفيذ واختبار حقيقيين |
| Streaming لتوليد النص | نمط تنفيذ/تسليم، لا Operation جديدة | تثبيت semantics الآن؛ ترك binding النقل لاختيار صريح | أحداث موحدة، حدث نهائي واحد، أخطاء وإلغاء؛ Provider/Model معلن ومختبر |
| `generate_audio` | Operation منفصلة عن TTS | قرار مشروط: أضفها إذا كانت الموسيقى/المؤثرات الصوتية استخدامًا أساسيًا | تعريف input/output واضح، تنفيذ واختبار، ونتيجة Asset Reference |
| `search_web` | مرشح Operation | أضفها فقط إذا كان البحث خدمة Gateway مشتركة ومطلوبة للإطلاق؛ وإلا Tool لاحقة | مصدر بحث حقيقي، دلالات موحدة، وقت تحديث ومراجع نتائج، واختبارات |
| `analyze_video` | مرشح Operation أو امتداد لإدخال متعدد الوسائط | لا تُدرج قبل إثبات أن لها معنى مستقلًا عن تحليل إطار/ملف عبر موديل Vision | دعم زمني/إطارات واضح، موارد، وتنفيذ قابل للاختبار |
| استخراج المستندات | مرشح Operation أو Tool مركبة | أَجّله ما لم يكن استخراج النص/الحقول مهمة أساسية مستقلة | عقد موحد، معالجة AssetRef، واختبار على أنواع مستندات محددة |
| `tool_calling` | Capability | ليس Operation مستقلة؛ الموديل يخرج طلب Tool، وطبقة التنفيذ الأعلى تتصرف فيه لاحقًا | إثبات أن الموديل يدعم الشكل المعلن؛ Gateway لا ينفذ أمر نظام نيابة عنه |
| تنفيذ أوامر النظام | Tool آمنة في Agent مستقبلًا، خارج Gateway Provider Adapter | استبعاده من عقد المزوّدين | عزل sandbox وسياسات وصلاحيات ومراجعة مستقلة؛ خارج نطاق هذه المرحلة |
| `upload_asset` / `download_asset` | نقل/خدمة أصول | لا تحوّلهما تلقائيًا إلى Operations لكل Provider؛ ابدأ بعقد Asset Reference | إذا احتاج Gateway خدمة تخزين/نقل فعلية، تُعتمد كخدمة مستقلة بحدود أمنية واضحة |
| `run_provider_agent` | تفويض/تنسيق Agent خاص بالمزوّد | أوصي ببقائه مستبعدًا من العقد الأساسي | لا يُعاد بحثه إلا بقرار معماري صريح؛ وجوده يطمس مسؤولية Agent Core |

## 3. Capability vocabulary مقابل الدعم

يجوز أن تحتوي وثيقة المفردات على IDs عامة حتى لو لم يدعمها أي Provider بعد، مثل:

- `audio.transcription`
- `audio.speech_synthesis`
- `audio.generation`
- `video.generation`
- `text.streaming`
- `tool.calling`
- `vision.image_input`

هذه أسماء قاموس فقط. لا تعني توفرها لدى Provider أو Model. الدعم التشغيلي يعلن في تعريف Provider/Model فقط بعد وجود تنفيذ واختبار. في تصميم vNext يُفضّل أن تكون Capabilities قائمة IDs إيجابية مدعومة؛ الغياب يعني «لم يُعلن الدعم»، ولا يُفهم كضمان استحالة الدعم.

## 4. Model واحد عند أكثر من Provider

لا نفترض هوية عالمية للموديل. إذا أعلن Provider A وProvider B الاسم نفسه، فهما مدخلان منفصلان بهوية مركبة `(provider public name, model name)`؛ قد تختلف العمليات والقدرات والسعر/القيود حتى لو تطابق الاسم. هذا يكفي لاختيار SDK الحالي، إذ يتطلب `provider` و`model` معًا.

لتقليل عبء الإضافة، يعلن Provider عمليات/قدرات افتراضية إذا كانت تنطبق على كل موديل، وتُضاف `support` اختيارية فقط للموديل الاستثنائي. Discovery يعرض الدعم الفعلي المحسوب لكل موديل. لا نغيّر أسماء الموديلات ولا نضيف IDs عالمية؛ اختيار Agent Core لاحقًا يتم من الزوج الحالي `(provider, model name)`.

## 5. مصفوفة التعريفات الحالية

جرد الحزم المكتشفة حاليًا (14 مجلد Provider مكتملًا) موجود في [`CURRENT_CONTRACT_REVIEW.md`](CURRENT_CONTRACT_REVIEW.md). المصفوفة مشتقة من التعريفات وملفات metadata في الفرع، وليست قائمة في SDK ولا وعدًا بأن كل Model يطبق كل عملية Provider-level.

## 6. معيار ترقية مرشح إلى Operation أساسية

لا تُقبل Operation في العقد/الكتالوج التشغيلي إلا إذا توفرت كل الشروط:

1. معنى موحد لا يعتمد على اسم endpoint خاص بمزوّد.
2. عقد request/result وأخطاء وtimeouts واضح وقابل للتوثيق.
3. Adapter منفذ فعليًا لعملية واحدة على الأقل على Model معلن.
4. اختبارات عقدية ومحلية وDiscovery تثبت التنفيذ والنتيجة.
5. وصف صريح لنمط التنفيذ: sync، stream، أو job؛ لا تخلط بينها.
6. إدراجها في نتائج Discovery فقط عند توفر التنفيذ في نشر Gateway الحالي.

قائمة المرشحين في هذا المستند لا تصبح تلقائيًا جزءًا من `GatewayOperation` أو API v1. يلزم اعتماد المستخدم وقرار ترقية واضح.
